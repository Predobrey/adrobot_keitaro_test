# Adrobot — управление кампаниями и офферами Keitaro

Тестовое задание ETOLEGKO: веб-приложение для создания кампаний в Keitaro и редактирования распределения офферов в существующих потоках.

**Стек:** Python 3.12, FastAPI, SQLAlchemy 2, Alembic, SQLite; Next.js 16 (App Router), React 19, TypeScript. Интерфейс — на русском языке.

> **Назначение:** локальное приложение для работы с Keitaro Admin API. Это не самостоятельный рекламный трекер: кампании, потоки, офферы и маршрутизация трафика хранятся в Keitaro. Для использования основных функций нужны действующие права доступа к Keitaro.

## Возможности

**Создание кампании**

- Название, один или несколько GEO-кодов ISO 3166-1 alpha-2 (например, `AU` или `AU,MX`), существующий оффер, домен, группа кампаний и источник трафика.
- Кампания создаётся **выключенной**; затем добавляются два потока:
  1. `forced` — фильтр по указанным странам (`country`, `accept`), HTTP-редирект на Google.
  2. `default` — оставшийся трафик на выбранный оффер (100%).
- Ротация потоков — по позиции (`position`). После создания потоков кампания включается, затем приложение повторно проверяет список потоков по их ID.
- Домен передаётся в Keitaro через `domain_id`; группа и источник — через `group_id` и `traffic_source_id`.

**Редактор офферов**

- Загрузка кампаний, выбор потока с офферами, добавление доступных офферов, удаление из выбранного потока и восстановление до отправки изменений.
- Автоматическое целочисленное распределение процентов: `50/50`, `34/33/33`, `25/25/25/25`; возможность закрепить долю.
- Кнопки **Отменить** и **Сохранить в Keitaro**. Изменения не отправляются после каждого нажатия — только по подтверждению.
- Проверка суммы долей (ровно 100%), повторное чтение потока после сохранения, сохранение уже отключённых офферов и неизменность прочих параметров маршрутизации.

## Требования перед запуском

| Компонент | Версия / назначение |
| --- | --- |
| Python | **3.12** (проверенная версия для проекта) |
| Node.js | **22.6+**; нужен для `node --experimental-strip-types` в тестах |
| npm | Поставляется с Node.js; используется `npm ci` |
| Git | Для клонирования репозитория (или можно скачать ZIP) |
| Keitaro | Доступ к **Admin API**, действующий API-ключ, существующие оффер, домен, группа и источник |

По умолчанию backend работает на `127.0.0.1:8000`, frontend — на `127.0.0.1:3000`. Запускайте их **в разных терминалах**. Docker и внешняя СУБД для локального запуска не нужны.

## Быстрый старт: Windows (PowerShell)

Команды ниже выполняются из **корня клонированного или распакованного репозитория**, если не указано иное.

### 1. Backend: первый терминал

```powershell
# Проверяем установленный Python
py -3.12 --version

# Создаём и активируем окружение в КОРНЕ проекта
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1

# Устанавливаем Python-зависимости
python -m pip install -r .\backend\requirements.txt

# Создаём локальную конфигурацию только один раз
Copy-Item .\backend\.env.example .\backend\.env
notepad .\backend\.env
```

В открытом `.env` укажите свой адрес Keitaro и API-ключ (поля описаны ниже). **Не добавляйте настоящий ключ в исходники или Git.** Если `backend/.env` уже существует, повторно копировать шаблон не нужно — это перезапишет настройки.

```powershell
# Важно: миграцию и backend запускаем ИЗ backend/
cd backend
python -m alembic upgrade head
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Проверка запуска:

- <http://127.0.0.1:8000/docs> — Swagger UI с методами API.
- <http://127.0.0.1:8000/api/health> — JSON со статусом `ok` и флагом `keitaro_configured`.

`keitaro_configured=true` означает, что конфигурация **заполнена**, а не что соединение с трекером уже проверено. Для фактической проверки чтения данных откройте приложение после запуска frontend.

> Если PowerShell блокирует `Activate.ps1`, можно выполнить `Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned` в **текущем терминале**, а затем повторить активацию. Это временная настройка для одной сессии. Либо вызывайте `\.venv\Scripts\python.exe` напрямую, без активации (из корня проекта).

### 2. Frontend: второй терминал

Откройте **новый PowerShell**, оставив терминал с FastAPI работающим:

```powershell
# Из корня проекта
cd frontend
npm ci
npm run dev
```

Откройте **<http://127.0.0.1:3000>**. В интерфейсе доступны «Создать кампанию» и «Редактор офферов».

Next.js принимает запросы браузера на `/api/*` и пересылает их в FastAPI. Браузер **не получает** ключ Keitaro.

### 3. Повторный запуск

В первом терминале, из корня проекта:

```powershell
.\.venv\Scripts\Activate.ps1
cd backend
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Во втором терминале, из корня проекта:

```powershell
cd frontend
npm run dev
```

При повторном запуске не нужны `venv`, `pip install`, `npm ci` и миграция, если зависимости или схема БД не менялись.

## Конфигурация

### `backend/.env`

Создаётся из `backend/.env.example` и читается backend при запуске **из папки `backend/`**:

```dotenv
KEITARO_BASE_URL=https://tracker.example.com
KEITARO_API_KEY=CHANGE_ME
DATABASE_URL=sqlite:///./adrobot.db
GOOGLE_REDIRECT_URL=https://www.google.com/
```

| Параметр | Значение |
| --- | --- |
| `KEITARO_BASE_URL` | **Корневой адрес** Keitaro без `/admin` и без `/admin_api/v1`. Для удалённого трекера используйте HTTPS. |
| `KEITARO_API_KEY` | Ключ **Keitaro Admin API**. Отправляется backend в заголовке `Api-Key`. |
| `DATABASE_URL` | URL SQLAlchemy. По умолчанию локальная SQLite: файл `backend/adrobot.db`, если команды выполняются из `backend/`. |
| `GOOGLE_REDIRECT_URL` | URL для первого GEO-потока; по умолчанию `https://www.google.com/`. |

При изменении `backend/.env` **перезапустите FastAPI**. Для запросов на запись нужны соответствующие права в Keitaro; наличие ключа ещё не означает разрешение на любые действия.

### `frontend/.env.local` — необязательно

По умолчанию Next.js обращается к `http://127.0.0.1:8000`. Для другого backend создайте `frontend/.env.local`:

```dotenv
API_PROXY_TARGET=http://127.0.0.1:8000
```

`API_PROXY_TARGET` — **серверная** переменная в `frontend/next.config.ts`; при её изменении перезапустите Next.js. Не записывайте сюда Keitaro API-ключ. Для обычного локального запуска этот файл вообще не нужен.

## Как проверить функциональность

### Создание кампании

1. В «Создать кампанию» укажите название (в общем тестовом Keitaro используйте префикс, выданный работодателем), GEO-код из двух букв, существующий оффер, домен, группу и источник.
2. Перед подтверждением проверьте GEO → Google и остальные страны → оффер. **Кнопка реально записывает данные в Keitaro.**
3. Если создание прошло успешно, найдите кампанию в Keitaro и убедитесь, что у неё два потока, правильные фильтр, домен, группа и источник.
4. Если создание вернуло ошибку после начала операции, **не повторяйте его вслепую**: в Keitaro могла сохраниться частично созданная кампания. Найдите её по имени/ID и проверьте потоки.

### Редактор офферов

1. В «Редактор офферов» выберите разрешённую кампанию и её поток **с офферами**.
2. Добавьте или удалите оффер, при необходимости закрепите процент. Незакреплённые офферы делят оставшиеся целые проценты поровну.
3. Проверьте сумму **100%**, затем нажмите «Сохранить в Keitaro» и подтвердите запись. До этого действия сервер не изменяется.
4. После записи приложение запрашивает поток повторно и сверяет сохранённые значения. «Отменить» возвращает несохранённое состояние к исходному.

Нельзя сохранить нулевое количество активных офферов, повторяющиеся ID или сумму, отличную от 100%. Например, **один закреплённый оффер с долей 10%** будет заблокирован для сохранения, пока распределение не станет корректным.

На момент последней локальной проверки V8: **48 backend-тестов и 34 frontend-теста**, TypeScript, ESLint и production build — без ошибок. Тесты работают с фиктивными ответами Keitaro и **не изменяют** его общие данные.

Для локального запуска собранного frontend вместо `npm run dev` можно использовать `npm run build`, затем `npm run start`; это **не** означает готовность приложения к публичному развёртыванию.

## Миграции и локальная база

- ORM: SQLAlchemy; миграции: Alembic (`backend/alembic/versions/0001_initial.py`).
- Перед **первым** запуском из `backend/` выполните `python -m alembic upgrade head`. После обновления кода повторите команду, если появились новые миграции.
- В SQLite хранятся `campaign_domains` (локальная информация о выбранном домене) и `operation_log` (история действий). **Кампании, потоки и офферы не дублируются** в этой базе — источником истины является Keitaro.
- `backend/adrobot.db` создаётся локально и исключён из Git. Удаление этого файла удалит **локальную** историю/связи, но не кампании Keitaro; не используйте удаление базы вместо миграций.
- `alembic downgrade` не требуется для обычного запуска и может удалить локальные таблицы.

Подробности backend и контрактов API: [backend/README.md](backend/README.md).

## HTTP API Adrobot

| Метод и маршрут | Назначение |
| --- | --- |
| `GET /api/health` | Статус FastAPI и признак заполненной конфигурации |
| `GET /api/meta` | Списки офферов, доменов, групп и источников из Keitaro |
| `GET /api/campaigns` | Список кампаний |
| `POST /api/campaigns` | Создание кампании с двумя потоками |
| `GET /api/campaigns/{id}/streams` | Потоки выбранной кампании |
| `GET /api/streams/{id}` | Состояние конкретного потока |
| `PUT /api/streams/{id}/offers` | Обновление состава и долей офферов |

Swagger: <http://127.0.0.1:8000/docs>. FastAPI на корневом `/` перенаправляет на `/docs`; пользовательский интерфейс запускается **только в Next.js**.

## Частые проблемы

| Симптом | Что проверить |
| --- | --- |
| `py -3.12` не найден | Установите Python 3.12 и проверьте `py -0p` либо путь к `python`. |
| PowerShell запрещает `Activate.ps1` | Временно разрешите скрипты для текущего процесса или запускайте Python из `.venv` напрямую. |
| `ModuleNotFoundError: app` / Alembic не находит настройки | Запускайте `uvicorn`, `pytest` и `alembic` **из `backend/`**, как в примерах выше. |
| Не появляется `backend/adrobot.db` | Проверьте `DATABASE_URL`, текущую директорию и выполненную миграцию. |
| Next.js сообщает об ошибке FastAPI / `502` от `/api` | Убедитесь, что Uvicorn работает на `127.0.0.1:8000`; проверьте `API_PROXY_TARGET` и перезапустите Next.js. |
| `/api/health` отвечает, но списки пусты / ошибка подключения | Проверьте адрес и ключ в `backend/.env`, права Admin API и HTTPS. `keitaro_configured` не проверяет доступность трекера. |
| Keitaro возвращает `403` | У ключа нет прав на операцию. Не пытайтесь обходить ограничения; обратитесь к владельцу тестового окружения. |
| Keitaro возвращает `422` | Посмотрите сообщение в интерфейсе или ответ Swagger: обычно отклонено конкретное поле запроса. |
| Кампания частично создана | Проверьте её в Keitaro перед повторным созданием; повторный запрос может создать дубль. |
| Порт 3000/8000 занят | Остановите прежний процесс либо настройте разные порты и `API_PROXY_TARGET` согласованно. |

## Ограничения тестовой среды и безопасность

- В предоставленном общем тестовом Keitaro был доступен **один оффер**. Попытка создания дополнительного через Admin API вернула `403 Forbidden`. Поэтому сценарии распределения нескольких офферов **проверены автоматическими тестами с моками, а не живой записью**. Создание кампании и чтение её настроек проверялись на реальном тестовом Keitaro.
- Adrobot **не создаёт новые офферы**: это не требуется в ТЗ. Для проверки добавления нужны заранее существующие доступные офферы.
- Не изменяйте чужие кампании или каталог офферов в общей среде. Приложение предназначено для локального использования, **без авторизации собственных пользователей**; не выставляйте порты приложения в публичный интернет без отдельной защиты.
- Никогда не коммитьте `.env`, `.venv`, `node_modules`, `.next`, локальные базы и ключи. Для проверки перед публикацией можно выполнить `git ls-files | Select-String -Pattern '(^|/)\.env$|(^|/)\.venv/|(^|/)node_modules/'` в PowerShell из корня — список должен быть пустым.
